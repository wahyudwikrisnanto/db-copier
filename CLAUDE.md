# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Wails v2 desktop app (Go backend + React 19 / Tailwind v4 / shadcn/ui frontend) that clones a PostgreSQL database, optionally reached through an SSH tunnel, into another database. Every copy **erases the target first**.

## Commands

Linux builds require the `webkit2_41` build tag (needs `libgtk-3-dev libwebkit2gtk-4.1-dev`). The Makefile wraps this:

```sh
make dev      # wails dev -tags webkit2_41 (hot reload), via scripts/clean-env.sh
make build    # wails build -tags webkit2_41, binary in build/bin/
make run      # build + launch
make test     # go test ./internal/...
```

- Single test: `go test ./internal/pg -run TestEraseStatements -v`
- Frontend type-check/build: `cd frontend && npm run build` (`tsc && vite build`). There is no linter or frontend test suite.
- `main.go` embeds `frontend/dist`, so `go build`/`go vet` of the root package fails until the frontend has been built once.
- Integration tests (`//go:build integration`, gated by `DB_COPIER_IT=1`) need the three docker containers described in README.md (source :5433 behind SSH :2222, target :5434):
  `DB_COPIER_IT=1 go test -tags integration ./internal/copier -v`
- Store tests set `DB_COPIER_NO_KEYRING=1` to force the file-based secrets fallback; do the same in any new test touching `store`.

## Architecture

Copy flow (`App.StartCopy` → `copier.Copier.Run`):
1. `copier.OpenSession` opens an SSH tunnel per connection if needed (`internal/tunnel`, random local port on 127.0.0.1, TOFU host keys pinned in `<configDir>/known_hosts`) and yields a resolved `pg.Endpoint`.
2. Checks `pg_dump` major version ≥ source server major.
3. `pg.Erase` drops all non-system schemas, extensions (except plpgsql) and event triggers, then recreates `public` — all in one transaction.
4. Streaming mode (`Options.Jobs` ≤ 1): `Copier.pipe` streams `pg_dump --format=custom` stdout into `pg_restore` stdin via `io.Pipe`. Either process failing cancels the other; parent-context cancellation returns the literal error `"cancelled"`. `pg_restore` stderr lines containing `error:` are collected and surfaced as the failure message. Passwords are passed via `PGPASSWORD` env (`pgEnv`), never argv.

Parallel mode (`Options.Jobs` > 1, `Copier.runParallel`) changes the order: `pg_dump -Fd --jobs=N --compress=zstd:1` into a temp dir under `os.UserCacheDir()/db-copier/dump-*` (not `os.TempDir`, often tmpfs), and only **then** erases the target and runs `pg_restore --jobs=N`. With `--jobs`, pg_restore's "errors ignored" count doesn't match printed error lines, so `restoreErrors.result` judges by the printed lines.

Backend/frontend boundary:
- `App` (app.go) is the only Wails-bound struct; its exported methods become JS functions in the generated `frontend/wailsjs/` (regenerated by `wails dev`/`wails build` — don't edit by hand).
- Only one copy runs at a time (`App.cancelCopy` guarded by a mutex). Events are coalesced by `logBatcher` (150 ms ticks, also the `copier.Reporter`): `copy:log` (batches of lines), `copy:progress` (latest `copier.Progress` snapshot), `copy:tables` (batches of finished table names); `copy:plan` (table sizes from `pg.LoadPlan`) is emitted once directly, and `copy:done` carries `CopyResult`.
- Progress is derived in `internal/copier/progress.go` by parsing `pg_restore --verbose` lines (`creating …`, `processing data for table …`) and counting bytes through the dump→restore pipe (dump runs with `--compress=0` so that count tracks table sizes). Totals are estimates; the frontend computes overall percent from phase weights in `components/CopyProgress.tsx`.
- `frontend/src/lib/api.ts` wraps the generated bindings and redeclares the Go types as plain TS interfaces (JSON shape only). When changing a Go struct's JSON fields or an `App` method, update `api.ts` to match.
- Colors: use only the design palette defined in `frontend/src/index.css` (blue primary, teal secondary, slate neutral, success/warning/danger/info with `-bg`/`-border`, `source`/`target`, `status-*`, `diff-*`, surface/text tokens), exposed as Tailwind utilities (`text-success`, `bg-status-running`, `text-source`, …). shadcn vars (`--primary`, `--destructive`, …) are aliases onto it. Never use raw Tailwind color scales or hex in components (exception: user-picked `connectionColors` in `api.ts`). Dark overrides sit under `.dark, [data-theme="dark"]`; add new colors to the palette first.
- Frontend is a single-shell app (`App.tsx`) switching between `pages/{Copy,History,Connections,Settings}Page.tsx`; no router (the selected history job id lives in `App.tsx` state, `HistoryPage` swaps in `JobDetailPage`). `components/ui/` is shadcn-generated.

Activity history (`internal/history`): every job is recorded under `<configDir>/history/<id>/` as `job.json` (summary, `Job`), `copy.json` (plan, last progress, finished tables — enough to redraw `CopyProgress`) and `log.txt` (appended through `logBatcher`, which forwards to a `history.Recorder`). Jobs carry a `Kind` (`copy` now, `query` reserved for a future query executor) and connection snapshots (`ConnRef`, no secrets). Jobs still `running` at startup are marked failed (interrupted); only the newest `MaxJobs` are kept. `App` emits `history:changed` on start/finish/delete; `CopyResult.jobId` links a finished copy to its record.

Persistence (`internal/store`): connections and settings in `~/.config/db-copier/connections.json`; passwords/passphrases go to the OS keyring, falling back to a `0600` `secrets.json` when no keyring service is available. Writes are atomic (`writeFileAtomic`).

`pg_dump`/`pg_restore` paths come from Settings, else `PATH` lookup (`resolveBin` in app.go).

## Linux / VS Code snap quirk

The VS Code snap terminal injects GTK/GIO env vars that crash GTK apps. `snapenv_linux.go` (`fixSnapEnv`, called first in `main`) re-execs the binary with the `*_VSCODE_SNAP_ORIG` values restored; `scripts/clean-env.sh` does the same for `wails dev`/run in the Makefile. Keep both in sync if changed.
